# Архитектура решения (кратко, не успеваю аааааа)

В целом идея пришла почти сразу: как то посчитать векторы объявлений и итемов, и брать самые близкие. Слышали про 2 башни? Делал примерно это, дообучивал SentenceTransformer (rubert-tiny). Проблема в том, что тут есть и не текстовые фичи, которые тоже хочется как-то использовать (и как показывает EDA, локация это очень важная фича). Вот тут особо мудрить не стал (но пытался), и просто сделал банальный MLP, который для пары (query, item) будет давать ей скор. На вход подаются эмбеддинги текстовых полей (кроме infm_params_text, потому что там данные выглядят все таки категориальными), категориальные и численные фичи (например 1 если item и query имеют одинаковую локацию).
